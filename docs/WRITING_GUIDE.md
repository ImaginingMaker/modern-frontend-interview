# 内容编写规范

## 固定结构

每个章节必须包含 frontmatter、章节目标或题目索引、与目录一致的显式英文锚点、复习内容和“权威来源”。每道核心题依次写：

1. `InterviewMeta`：难度、频率、岗位、核验日期
2. 一句话结论
3. 原理详解与最小可运行示例
4. 常见追问
5. 易错点或过时说法
6. 工程场景

## 标题与锚点

- 路由与锚点只使用小写英文、数字和连字符。
- 标题必须显式写 `{#stable-anchor}`，目录中的 topic ID 与之完全一致。
- 改名时默认保留旧锚点；确需删除时先修复所有引用。

## 分级规则

- ★：名词理解；★★：能正确使用；★★★：能解释机制。
- ★★★★：能处理边界和故障；★★★★★：能做跨层权衡与系统设计。
- 频率为低/中/高/极高；岗位为校招/初级/中级/高级。

## 来源与时效

- 优先级：正式标准与 RFC → 官方文档/发布说明 → MDN/web.dev → 高质量二手资料。
- 实验提案必须注明阶段和核验日期，禁止写成稳定能力。
- 引用只支持论断，不复制长段原文；代码优先重写成最小示例。
- 每次修改版本化内容时更新 `updatedAt` 和来源核验日期。
